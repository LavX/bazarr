# Bazarr+ v2.8.0 (Cortex)

Codename: **Cortex** (opening the v2.8 line).

---

## Headline: Embedded tracks get the tools external subtitles already had

A subtitle track inside the video file used to be a dead end in Bazarr+. The row listed its language and offered Translate, while Sync, the cleanup tools, Edit, View, Download and Delete stayed disabled, because those tools need a file on disk and this track is inside the container. A PGS or VobSub track could not even be translated: the click failed after the fact, because the row did not know its own format.

v2.8 turns the track into a file on demand and composes everything from that. Bazarr+ still never rewrites a media file.

### Extract to file

**Extract to file** pulls the track out with ffmpeg and writes it next to the video as an ordinary subtitle, named with the video's name, the language, any HI or forced tag, and the extension. A hearing-impaired English track becomes `<video>.en.sdh.srt` when the HI extension is set to `sdh`, a forced one becomes `<video>.en.forced.srt`, and a plain one becomes `<video>.en.srt`. The file goes into the folder set under **Settings > Subtitles > Subtitle Folder**, or beside the video when that setting is **Next to the video file**. Text tracks always come out as SRT.

Image-based tracks are copied out as they are: `.sup` for PGS, an `.idx` plus `.sub` pair for VobSub, and `.mks` for DVB. Those files are for players and are not listed as text subtitles.

Nothing is overwritten. A file already at the target name makes the action refuse and name the file, and a text track in single-language mode also counts any language-less subtitle of the video (`<video>.srt`, `<video>.ass` and so on) as taken, so you can delete or rename it and run the action again. A finished extraction gets its own History entry, **Extracted**, keeps the source track's score, and the item is indexed again, so the new file is an ordinary external subtitle from then on. Like an embedded track, an extracted file counts as source quality, so the upgrade job leaves it alone.

**Extract Embedded Tracks** on the Movies, Series and Sports lists does the same in bulk: every indexed embedded track whose language has no subtitle file yet is written out, whether or not your language profile wants that language, and covered languages and hidden tracks are left alone. Coverage is checked by language plus the HI and forced flags, so an existing plain English file does not suppress an English HI or forced track.

### The same tools, one job

On a text track the row menu offers Sync, Change Frame Rate, Adjust Times, the cleanup tools and Add Color, plus View, Edit and Download. The extraction and the tool are one job: the SRT is written to the subtitle folder first, then the tool runs on it, and the result stays there. Two-Point Fit stays disabled on an embedded row, because it reads its two lines from the row's own subtitle file, and an embedded row has none.

- **Edit** opens the track in the editor as a new subtitle, already filled in. Nothing is written until Save; Save creates the external file.
- **View** opens the same text in the preview and writes nothing beside the video.
- **Download** saves the text to your computer without creating a library file.
- **Translate** keeps its previous path: it extracts into `{config_dir}/extracted_subs/`, translates that copy, and writes only the translated subtitle, so no source copy appears next to the video.

### Image-based tracks

PGS and VobSub rows offer **Extract to file** and **Hide track** only, and the menu says why: the tools, View, Edit and Download need text, and an image-based track has none. With the default ffprobe parser Bazarr+ does not learn the format of a DVB track at index time, so a DVB row can look like a text track and its text actions fail when run; **Extract to file** still copies it out as `.mks`.

### Hide track

Delete is replaced by **Hide track...** on embedded rows, because Bazarr+ never rewrites a media file. It stops listing the track for that title and treats the language as wanted again, so a later search can download a text subtitle. The track stays inside the video and nothing is deleted.

Tracks are told apart by language, HI and forced only, so an English SRT track and an English PGS track on the same title are hidden together, and the confirmation lists every track the hide covers. When another subtitle still covers the language, or the language profile does not want it, Bazarr+ says so and does not search.

Hidden tracks appear as **Hidden tracks (n)**, under the subtitle table on a movie and in the subtitle cell of the episode or event on series and sports pages, and each one has **Unhide**. Bazarr+ indexes the video again at once, and if the file cannot be read at that moment the next index lists the track.

### What changes for existing libraries

- A VobSub pair (`Film.en.idx` plus `Film.en.sub`) no longer lists its `.sub` half as a text subtitle from the first index after upgrading. If the pair was the only subtitle of a language, that language now shows as missing and an automatic search may download a text subtitle beside it. The pair itself is kept.
- Titles indexed before the upgrade have no stored track format. Until a title is indexed again (Scan Disk, or the scheduled Index All Existing Subtitles tasks), its embedded rows show no format badge, and a PGS or VobSub row still gets the text menu.
- Downgrading after extracting tracks is safe for the files. **Before you downgrade, restore a database backup taken before you upgraded.** A 2.7.x install cannot open the 2.8 database, so without the backup it will not start. If you restore the backup and keep the extracted files, the files stay but their **Extracted** History entries do not, because the backup was taken before they were written. To 2.7.x an extracted file is then an ordinary external subtitle, and when an older download of the same language is still in History and its file is gone, its upgrade job can take the extracted file for the current subtitle of that language and replace it. 2.7.x also lists the `.sub` half of an extracted VobSub pair as a text subtitle.
