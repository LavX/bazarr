# Bazarr+ v2.8.0 (Cortex)

Codename: **Cortex** (opening the v2.8 line).

---

## Headline: Embedded tracks get the tools external subtitles already had

A subtitle track inside the video file used to be a dead end in Bazarr+. The row listed its language and offered Translate, while Sync, the cleanup tools, Edit, View, Download and Delete stayed disabled, because those tools need a file on disk and this track is inside the container. A PGS or VobSub track could not even be translated: the click failed after the fact, because the row did not know its own format.

v2.8 turns the track into a file on demand and composes everything from that. Bazarr+ still never rewrites a media file.

### Extract to file

**Extract to file** pulls the track out with ffmpeg and writes it next to the video as an ordinary subtitle, named with the video's name, the language, any HI or forced tag, and the extension. A hearing-impaired English track becomes `<video>.en.sdh.srt` when the HI extension is set to `sdh`, a forced one becomes `<video>.en.forced.srt`, and a plain one becomes `<video>.en.srt`. The file goes into the folder set under **Settings > Subtitles > Subtitle Folder**, or beside the video when that setting is the current folder. Text tracks always come out as SRT.

Image-based tracks are copied out as they are: `.sup` for PGS, an `.idx` plus `.sub` pair for VobSub, and `.mks` for DVB. Those files are for players and are not listed as text subtitles.

Nothing is overwritten. A file already at the target name makes the action refuse and name the file, and a text track in single-language mode also counts a language-less `<video>.srt` as taken, so you can delete or rename it and run the action again. A finished extraction gets its own History entry, **Extracted**, keeps the source track's score, and the item is indexed again, so the new file is an ordinary external subtitle from then on.

**Extract Embedded Tracks** on the Movies, Series and Sports lists does the same in bulk: every listed embedded track whose language has no subtitle file yet is written out, and covered languages are left alone. Coverage is checked by language plus the HI and forced flags, so an existing plain English file does not suppress an English HI or forced track.

### The same tools, one job

On a text track the row menu offers Sync, Change Frame Rate, Adjust Times, the cleanup tools and Add Color, plus View, Edit and Download. The extraction and the tool are one job: the SRT is written next to the video first, then the tool runs on it, and the result stays there. Two-Point Fit is not offered on an embedded row, because it picks its two lines from a file you choose.

- **Edit** opens the track in the editor as a new subtitle, already filled in. Nothing is written until Save; Save creates the external file.
- **View** opens the same text in the preview and writes nothing beside the video.
- **Download** saves the text to your computer without creating a library file.
- **Translate** keeps its previous path: it extracts into `{config_dir}/extracted_subs/`, translates that copy, and writes only the translated subtitle, so no source copy appears next to the video.

### Image-based tracks and OCR to text

PGS, VobSub and DVB rows offer **Extract to file** and **Hide track** only, and the menu says why. PGS and VobSub rows also offer **OCR to text...**: ffmpeg renders the cues, Tesseract reads them, the OCR Fixes mod cleans the text, and an SRT is written next to the video the same way Extract to file writes one. DVB is not supported. A row that does not know its track's format may ask for a Scan Disk first.

The first run in a language downloads that language's Tesseract pack into `{config_dir}/tessdata`, or the folder set under **Settings > Subtitles > Embedded Subtitles Handling > OCR Language Packs Folder**, and verifies its checksum. Without internet access the job fails with the download URL and the folder, so the pack can be placed there by hand; a hand-placed pack is accepted when its checksum matches. Italics are not preserved. The image grows by about 16 MB for the OCR wheels.

OCR is manual and runs as a job with progress, one run at a time. An 867-cue PGS track took about three and a half minutes in a measured run at a lowered CPU priority; a slow NAS can take fifteen minutes or more. The result is recorded in History as **Extracted** with the provider `ocr-tesseract`. **OCR Image Subtitles** on the Movies, Series and Sports lists reads the image tracks the language profiles still want, one after another.

### Hide track

Delete is replaced by **Hide track...** on embedded rows, because Bazarr+ never rewrites a media file. It stops listing the track for that title and treats the language as wanted again, so a later search can download a text subtitle. The track stays inside the video and nothing is deleted.

Tracks are told apart by language, HI and forced only, so an English SRT track and an English PGS track on the same title are hidden together, and the confirmation lists every track the hide covers. When another subtitle still covers the language, or the language profile does not want it, Bazarr+ says so and does not search.

Hidden tracks appear under the subtitle table as **Hidden tracks (n)**, and each one has **Unhide**. The next index lists the track again.

### What changes for existing libraries

- A VobSub pair (`Film.en.idx` plus `Film.en.sub`) no longer lists its `.sub` half as a text subtitle from the first index after upgrading. If the pair was the only subtitle of a language, that language now shows as missing and an automatic search may download a text subtitle beside it. The pair itself is kept.
- Downgrading after extracting tracks is safe for the files. **Before you downgrade, restore the pre-upgrade database backup.** A 2.7.x install cannot open the 2.8 database, so without the backup it will not start. If you restore the backup and keep the extracted files, the 2.7.x install shows their History entries as Unknown, and its upgrade job can treat an extracted subtitle as a download and replace it.
