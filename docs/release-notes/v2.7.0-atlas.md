# Bazarr+ v2.7.0 (Atlas)

Codename: **Atlas** (opening the v2.7 line).

For most of its life Bazarr+ has been a tool that waits for Sonarr or Radarr to tell it what exists. Atlas turns that around. It opens on **Discover**, where you can type the name of any film or show, owned or not, and have your providers answer while you watch. There is no library required, no key to paste, and nothing contacts a subtitle provider until you ask it to.

And it no longer needs an \*arr to be useful. With no Sonarr, Radarr or Sportarr at all, Discover is the whole app, and a library is something you can connect later if you ever want one. When you do run one, **Sports** is now a media type in its own right, with **Sportarr** as a third kind of library next to Sonarr and Radarr. **Emby** and **Silo** join Jellyfin and Plex, as many of each as you run, and each of them is asked to refresh when a new subtitle lands.

Around that, the setup wizard was rebuilt for people who arrive with nothing but a language, as well as for people who run four media servers. And every long action, from a download to a Provider Hub install, is now a job that finishes by telling you how it went and, when something failed, why.

**In this release:** Discover as the homepage · Sports with Sportarr · no \*arr required · several Emby and Silo servers · a rebuilt setup wizard · Statistics under System · jobs that report their outcome · session and container hardening · PostgreSQL backups that contain the database.

## Headline: Discover, subtitles for anything you can name

![Discover as the Bazarr+ homepage: the library hero over artwork, the Still missing queue and the Recently fetched row](https://raw.githubusercontent.com/LavX/bazarr/v2.7.0/site/screenshots/v2.7.0/discover-home.png)

Discover is where Bazarr+ opens now (#435, #443, #450). The top half is your own library: what it holds, what it is working on, and what is still missing, grouped per library with a link into each queue. A **Needs attention** panel collects throttled providers, disconnected library sync and unreachable root folders, and stays quiet when there is nothing to say. Below your library sit trending titles, digital releases and recent episodes from TMDB.

The part that changes how you use the app is the search box. Any film or show, by title or IMDb id, can be searched across your providers from its own title page, whether or not it is in your library, and whether or not you have a library at all.

### Why you will like it

- **It answers while it searches** (#520). Rows appear as each provider finishes, in the order they arrive, and you can download one while the rest are still working. On a real 36-provider install the first rows landed at 6.3 seconds on a search that finished at 21.2, and a subtitle was downloaded with 8 providers still pending.
- **It is honest about each provider** (#443, #520). A provider that cannot serve this request is shown apart from one that is unavailable, and a provider that never got to run is no longer reported as a timeout. A failing site backs off the way it does for a library search instead of being hit again every minute.
- **Preview before you commit** (#445). A formatted preview opens right under the row you picked, with the original text one click away.
- **Downloads are jobs** (#526, #536). Download queues a job with a readable name, and when the file is ready it saves itself with no second click and the row shows **Saved**. You do not have to wait on the page for it: the file is kept for up to 30 minutes, and **Save** in the Jobs drawer gets it later. If it fails, the row says why in plain words and offers **Retry** where another attempt can help.
- **Nothing costs a provider call you did not ask for.** Browsing and refreshing Discover never contact a subtitle provider. Back and Forward restore a finished search without searching again, and a search you walked away from mid-flight is kept (#513).
- **Request it in Seerr** (#453). If you run Seerr, Jellyseerr or Overseerr, a title page says what Seerr already knows and offers the matching action.

![A Discover search still running, with results already listed while the remaining providers answer](https://raw.githubusercontent.com/LavX/bazarr/v2.7.0/site/screenshots/v2.7.0/discover-live-results.png)

### Try this

1. Type a film you do not own into the search bar, open its title page, pick a language and press **Search**. Watch rows arrive, open **Preview** on one, then **Download** it. The file saves itself when the job finishes and the row shows **Saved**.
2. Open **Search details** under the results after a search finishes. It tells you how many providers searched, how many skipped the request and how many were unavailable.
3. If you run Seerr, add it under **Settings > Connections > Seerr**, then open a show you do not have. The season picker keeps what Seerr holds, what your library holds and what is left to request apart, so selecting everything cannot re-request what exists.

![A Discover title page for a film that is not in the library, with a Seerr request action and subtitle results from several providers](https://raw.githubusercontent.com/LavX/bazarr/v2.7.0/site/screenshots/v2.7.0/discover-title-subtitle-search.png)

![A Discover download for a film that is not in the library: the file saves itself when the job finishes, the row shows Saved and a notification names the saved file](https://raw.githubusercontent.com/LavX/bazarr/v2.7.0/site/screenshots/v2.7.0/discover-saved.png)

### Under the hood

Title and exact-episode retrieval run behind identity guards, so a numbering disagreement or an unresolved external identity cannot silently turn into a looser search. When an episode and its show disagree, the page now refetches both sides and always offers the manual path with the season and episode already filled in, instead of a warning with no way past it (#486). Result rows are built and given their download handle as each provider completes, and the final list reuses those same rows, so a handle offered mid-search stays valid. Provider outcomes are split into `timeout` (a deadline the provider owns), `abandoned` (still working when the shared wall fired) and `not_started` (never reached a worker), and `not_started` takes no cooldown and no health penalty, because nothing was asked. Discover now shares the global throttle table and provider health tracker with library searches, and a retry delay comes from the server's `Retry-After` first. Metadata comes from TMDB through the app's built-in key, which never appears in settings payloads, responses or logs; your own key remains an optional override. The TMDB feeds reuse one pooled connection per host, which took a cold warm-up of all three feeds from 48 connections and over 100 seconds to one connection and under two seconds (#454). Library covers now load through the image proxy of the instance that owns them, and every count names its unit, so "missing" episodes and missing languages no longer get mixed up (#450). The Seerr key is encrypted at rest and never logged, requests are made as the Seerr owner, which Seerr approves immediately, and the page says so beside the action.

## Headline: Sports, with Sportarr

![A Formula 1 league page listing race and qualifying events for the season with their audio and subtitle languages](https://raw.githubusercontent.com/LavX/bazarr/v2.7.0/site/screenshots/v2.7.0/sports-events.png)

Sports used to live beside series and movies on a parallel path. In Atlas it is a first-class media type, and **Sportarr** is a library kind alongside Sonarr and Radarr, with as many instances as you run (#432).

### Why you will like it

- **Everything you already do for an episode works for a race.** Manual search and download, uploads, the subtitle editor, sync, translation, combine, scheduled work, Wanted, History, Excluded, global search and library actions all cover sports recordings.
- **Leagues and events, the way you think about them.** The Sports page lists your leagues; a league page lists its events by season, with audio languages, subtitles and per-event actions on each row. **Combine across league** builds combined subtitles for a whole league in one job.
- **Profiles per league.** A league carries a language profile, set from **Change Profile** on the league or with **Mass Edit** across several, and that profile decides which languages its events look for.
- **Settings that fit sports.** Sportarr has its own minimum score for sports events, excluded tags, excluded sports, a monitored-only switch and search after sync, with global defaults and per-instance overrides.
- **Your media servers hear about it.** A new sports subtitle refreshes Plex and Jellyfin through their configured libraries, and Emby and Silo through their path mappings.

![The Sports library listing several leagues from a Sportarr instance with their language profiles](https://raw.githubusercontent.com/LavX/bazarr/v2.7.0/site/screenshots/v2.7.0/sports-leagues.png)

### Try this

1. Add Sportarr under **Settings > Connections > Sportarr**, test it and save. Give a league a language profile from its page.
2. Open an event and run a manual search, or open **Wanted** and let the missing sports subtitles queue up with everything else.
3. On a league page, try **Combine across league** and watch it run as one job with per-item progress.

### Under the hood

The owning Sportarr instance travels with every piece of work: asynchronous jobs, file access, history and provider callbacks all check it, rather than trusting the entry point. A persistent recording index moves file hashing out of request handling, background scans run in bounded batches with retries, and an unknown recording keeps its request retryable until selection is safe. Wanted eligibility and paging run in SQL. When an event moves, its history and blacklist follow only after the upstream identity agrees, and a failed move rolls back completely. A minimum score of zero is kept rather than read as unset, and legacy translated history with no score stays eligible for upgrades.

## Headline: No Sonarr, no Radarr, no problem

Bazarr+ no longer needs an \*arr at all. With no Sonarr, Radarr or Sportarr connected, Discover is the whole app: search any film or show, let your providers answer, preview a result and save the subtitle to the device you are reading on. If you ever want automatic fetching for a library, connect one later and the library half of the app appears beside what you already use.

### Why you will like it

- **The wizard asks who you are first** (#462). Right after Welcome it offers two honest paths: have subtitles fetched automatically for a Sonarr, Radarr or Sportarr library, or find subtitles for anything with no library. The answer shapes the step list and nothing else, and either choice can be changed later in Settings.
- **Sonarr is never required.** Every library step is optional, and one you leave untouched writes nothing at all (#518).
- **The app only shows what you have** (#496). The sidebar lists Series, Movies and Sports per connected kind, so an install with no library has no dead-end pages, and an install running only Radarr gets Movies and not Series.
- **No nagging** (#496, #497, #498). One line on Discover offers to connect a library, and you can close it for good.

![The setup wizard asking whether you run a library or want subtitles for anything with no library](https://raw.githubusercontent.com/LavX/bazarr/v2.7.0/site/screenshots/v2.7.0/wizard-intent.png)

![Discover on an install with no library: the global catalog opens the page and the sidebar lists no library pages](https://raw.githubusercontent.com/LavX/bazarr/v2.7.0/site/screenshots/v2.7.0/discover-no-library.png)

### Try this

1. Start a fresh container, choose **subtitles for anything** on the wizard's second screen, pick your language and install the recommended providers.
2. Land on Discover, search for a title and download a subtitle; it saves itself when it is ready.
3. Later, add Sonarr or Radarr under **Settings > Connections** and watch the library half and its sidebar pages appear.

### Under the hood

A fresh install with no library used to show the crash screen on Discover (#468). The summary read now checks that the answer is really a summary, so a reverse proxy's sign-in page or the app's own `index.html` served in its place counts as a failed read rather than a crash, and the library half renders only where an instance is enabled. An enabled instance with nothing indexed yet keeps its half, because that is where the page says a scan is running. Nothing about the no-library path writes a backend setting; the wizard's answer is local to the wizard.

## Headline: Emby and Silo, and every media server on one layer

Bazarr+ now talks to **several Emby servers and several Silo servers**, the way it already talked to several Sonarr and Radarr instances (#431). Both are new in this release. Jellyfin and Plex moved onto the same layer (#466), so all four media servers work the same way: named instances, each with its own settings, status and retry.

### Why you will like it

- **The subtitle shows up in your server.** After a download or upload, Bazarr+ asks every enabled server that holds the file to refresh it natively: Emby and Silo through their path mappings, Jellyfin and Plex through the libraries you chose. A server that cannot reach the file is skipped quietly instead of reported as an error.
- **One slow server does not hold up the rest.** Each server refreshes on its own background worker, with pending targets and **Retry pending** when it was unreachable.
- **Refresh on demand.** Every server gets a **Refresh libraries** action that asks it to re-read itself, scoped the way that server scopes.
- **Set them all up in the wizard** (#502, #518). Tick every kind you run, add a second Emby with **Add another**, and configure each server on a screen of its own.
- **See what is running** (#521). System > Status lists every media server with the version it reports, says so when one is unreachable, and keeps checking until it answers.
- **Two Jellyfins?** Register both.

![The setup wizard's media server step with several server kinds ticked and a second Emby added](https://raw.githubusercontent.com/LavX/bazarr/v2.7.0/site/screenshots/v2.7.0/wizard-media-servers.png)

![System Status listing each connected media server with the version it reports](https://raw.githubusercontent.com/LavX/bazarr/v2.7.0/site/screenshots/v2.7.0/system-status-servers.png)

### Try this

1. Open **Settings > Connections > Emby** or **Silo**, add a server with its URL, API key and path mappings, and press **Test**.
2. Download a subtitle for something that server holds, then look for it in the server without rescanning by hand.
3. Open **System > Status** to see every server's version side by side.

### Under the hood

A refresh target is resolved by walking a ladder and stopping at the first rung the server supports. Emby tries **provider id, then exact path, then title and year, then a library refresh**. Silo's Jellyfin-compatible API returns no provider ids at all, so Silo uses the exact path with a library scan as fallback, and Bazarr+ watches that scan to completion, so a Silo refresh is confirmed rather than merely requested. Jellyfin walks provider id, then title and year, then its configured libraries; Plex walks the IMDb guid, then a section update, which is all it ever did. Neither declares the exact-path rung, so **neither needs path mappings**, as before. Keys are encrypted at rest. Plex is converged for refreshes only: its account, OAuth, webhook and Autopulse features still read the existing Plex settings, and opening the Plex tab no longer silently re-picks and saves a server connection (#472). The Status page never waits on a server: versions are probed in the background, cached for ten minutes on success and one minute on failure, and retired when you edit a server's URL.

## Also new in Atlas

### A setup wizard rebuilt from the first screen

Beyond asking who you are and taking every media server you run, the wizard grew up in the details (#462, #499, #501, #518, #523, #525, #541).

- **One click installs every provider that needs no account**, read from the catalog manifests so the set stays right as the catalog changes (#501). Everything else is still one tick away.
- **Every step fits one screen** at 1920 by 1080, including the provider steps with the full catalog loaded, with Back and Continue always in view (#518, #525).
- **Set up later** asks before it ends onboarding, and leaving then stays left instead of bouncing back into the wizard. **Settings > General > Run first-time setup** brings the wizard back at Welcome, even in a browser that remembered a later step (#523, #525, #541).
- The Providers step can be skipped, and it says what that means: nothing is searched until a provider is enabled, which you can do from the Subtitle Hub any time (#523).
- Each step has its own address under `/setup/<step>`, so Back walks one step back and a reload stays put. The languages step starts from your browser's language, and what you typed survives Back, except API keys (#523).
- Provider installs report each result as it settles, required credentials are checked before Continue, and a catalog that failed to load says so with a Retry instead of looking empty (#518, #525).
- Seerr and an OpenRouter key for the translator are optional steps of their own, and a fresh install reaches the wizard again on first load (#462, #499).
- A wizard in progress survives this upgrade, including behind a reverse proxy on a subpath (#518).

### Statistics that answer something

**System > Statistics** is a real page now (#448, #455). **Activity** plots downloads per day with the share that arrived without a manual search. **Providers** shows downloads, mean match quality and blacklist rate side by side, so the provider high on downloads and high on blacklist rate, the one to turn off, finally stands out. **Quality** shows the spread of match scores and which languages you actually end up with. One filter row drives every tab.

The numbers are careful: scores are normalised per media type before averaging, a real zero score is counted rather than dropped, uploads and translations are left out of quality by default, and the same library produces the same histogram on SQLite and PostgreSQL.

![System Statistics on its Activity tab with the daily download chart](https://raw.githubusercontent.com/LavX/bazarr/v2.7.0/site/screenshots/v2.7.0/statistics-activity.png)

### Every long action is a job, and says how it went

The jobs queue could only ever say that a job had finished (#526, #527, #528, #529). Now a failed job says why in a single sentence, in its notification and in the Jobs drawer, with **Retry** when a second attempt can help. A finished job that has something for you, like a Discover download, offers it right there. Routine scheduled work stays quiet.

Downloads, uploads, syncs, subtitle tools and mods, scan disk, series and league combine, mass actions, Provider Hub installs and updates, editor translations and waveforms all run as jobs now. Saving a language profile returns at once while a **Recalculating missing subtitles** job does the library pass, so a slow library no longer makes a save look like it failed. A manual download that failed is listed as failed with its reason, where it used to be listed as completed, and tables refresh when the job finishes rather than when it is queued.

## Other Improvements & Fixes

### Translation

- **SmartFast** and **Custom** OpenRouter provider routing in the AI translator settings. SmartFast needs AI Subtitle Translator 2.0.0, Custom needs 1.3.4, and existing installs keep their current routing (#434).
- Reasoning set to **Disabled** is really disabled now, and a cleared setting counts as disabled too, which stops translations timing out on reasoning tokens (#456, #457).
- Translation progress stays visible until the file is published, and two translations running at once each keep their own progress, on their own job (#458, #527).
- A failed OpenRouter translation names the translator service's own reason on the job, and a partial translation is named Partially translated (#527).
- Episode and movie translations from an embedded track return at once and extract inside the job, so a bitmap track fails with a sentence naming the likely codec (#529).
- Real costs are no longer rounded to `$0.00`, and no duration is invented when the server reported none (#458).

### Subtitles and search

- Manual and translated subtitle upgrades are separate switches, both off on a new install (#476).
- A translated subtitle is replaced by a real one once, instead of being re-downloaded every upgrade cycle (#507).
- A failed search or download shows the actual reason, for episodes, movies and sports (#484, #487).
- A subtitle file with an empty cue is no longer rejected whole: the empty cue is dropped and the rest is kept (#526).
- Combined subtitles keep valid UTF-8 and BOM-marked Unicode, and a movie's translated badge follows the file on disk (#447).
- Editor keep-all sync previews work again, in a private workspace that is cleaned up afterwards (#463).
- Editor video playback works for media on an explicitly selected Sonarr or Radarr instance (#446).
- The editor waveform is generated once per file and track, cached under 200 MB (#527).
- Language profile lookups that crashed uploads and indexing are guarded (#433).

### Security

- One failed form login no longer produces a cookie that opens the log, the backup download and the cover proxies (#451).
- The legacy MD5 password upgrade no longer puts your plaintext password in the browser cookie (#451).
- CORS is off unless you turn it on; before, every route answered `Access-Control-Allow-Origin: *` (#451).
- The event socket refuses a connection that cannot prove who it is, by session cookie or API key (#451).
- Session cookies are `SameSite=Lax` and `HttpOnly`, with a `Secure` policy, a configurable lifetime and a configurable trusted proxy (#451).
- A Provider Hub plugin can no longer name itself after a Bazarr settings section to receive that section's secrets (#460).
- The connection tests only return a validated version string, instead of echoing whatever answered (#479).
- The container no longer hands the application tree to the runtime user, and the reference compose file runs read-only with all capabilities dropped but three (#464).

### Backups

- PostgreSQL backups now contain the database, written with `pg_dump`, and the image ships the client tools (#465).
- A restore stages everything first and aborts before the restart if any step fails, so nothing is half applied (#465).
- A successful restore reports success instead of a 503 (#470).

## Upgrade / Migration Notes

Pull the new image and restart. Schema migrations run on boot, and existing settings, language profiles, providers and instances carry over. **PostgreSQL remains fully supported and first-class**, and every migration in this release is covered on both engines.

A few things need a closer look.

**1. Jellyfin and Plex become instance rows on the first startup.** A one-time backfill reads your existing Jellyfin and Plex settings and creates one instance row per configured kind, under a durable marker. Nothing to do, and nothing changes about how your servers are refreshed.

- The **Jellyfin settings form is gone.** Jellyfin is edited as an instance under **Settings > Connections**, like the other three kinds, and its old settings section is import-only.
- The Jellyfin **"refresh all libraries"** maintenance button is **removed**. Use the per-instance **Refresh libraries** action on the instance card instead.
- **Plex is converged for refreshes only.** Its account panel, OAuth sign-in, server discovery, webhook helper, Autopulse generator and recently-added-date writes still read the scalar Plex settings and are unchanged. A Plex row is created only where Plex was genuinely configured, because its `ip`, `port` and `verify_ssl` ship with non-empty defaults.
- Neither Jellyfin nor Plex needs path mappings, exactly as before. If you have two Jellyfin servers, you can now register both.
- Listing Plex servers no longer re-picks and saves the fastest connection, and a stored Sonarr or Radarr base path of `/` is no longer rewritten to an empty string.
- A Plex API key or sign-in token still stored in the old encrypted format is now converted on startup. The conversion failed on every start with an `ImportError` in the log and left the old value in place (#533).

**2. Everyone is signed out once.** The session cookie changes, and a cookie from an older release cannot carry its stored password forward. Sign back in as usual.

Three settings behind this are read at startup, so **changing them needs a restart**: `auth.session_lifetime_days` (default 30 days, an idle window renewed on each request), `auth.cookie_secure` and `general.trusted_proxy`.

- Behind an HTTPS reverse proxy this instance cannot detect, set `auth.cookie_secure` to `always`. The default, `auto`, follows the scheme of each request.
- `general.trusted_proxy` defaults to `127.0.0.1`, the in-container supervisor hop. It is **one address, not a list**. If your reverse proxy runs in another container, set its address so forwarded headers are believed and per-visitor login rate limiting works. Clearing the field trusts nothing.
- If CORS is disabled in your settings, you will stop receiving the `Access-Control-Allow-Origin` header every route used to send. Turn CORS on deliberately if you need it.
- The legacy password upgrade is now silent. **Once an MD5 password is upgraded to PBKDF2, going back to upstream Bazarr means resetting the password in the config file.**

**3. If you run a custom compose file, compare it against the reference.** The shipped compose, the README, the install guide and the one-liner installer now set `read_only: true`, `tmpfs: /tmp` capped at `size=512m`, `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`, and add back exactly `CHOWN`, `SETUID` and `SETGID`. A bare `cap_drop: [ALL]` does not boot, because the entrypoint needs those three to hand `/config` to `PUID:PGID` and become that user. Adopting the hardened keys is optional, but the reference is what the project supports.

- The entrypoint now chowns `/config` only, not `/app/bazarr`, and drops to the numeric `PUID:PGID`.
- Managed binaries move to **`/config/managed/bin`**. The old location is still read, so an upgrade keeps the binaries it already has.
- The **in-app updater is gated off in the image**. Update by pulling a new image, as the Docker install always intended.
- If you mount a source tree over `/app/bazarr` for development, drop `read_only`.

**4. PostgreSQL backups need `pg_dump`, and the version has to match.** The image ships `postgresql-client`, so a normal install needs nothing. From source, install the PostgreSQL client tools, or `POST /api/system/backups` answers 500 naming the missing tool rather than writing a useless archive. The `pg_dump` client major version must be at least the server's: for a PostgreSQL 18 server, use an 18 or newer client.

Any backup you took on PostgreSQL before this release **does not contain your database**. Take a fresh one after upgrading. A restore now aborts before the restart if any step fails, and an archive without the database for this instance is refused before the restart.

**5. Existing installs keep their OpenRouter routing.** SmartFast is the default only on a genuinely new install. A config that predates the routing setting keeps `throughput`, and one that already names a usable routing keeps it. To use SmartFast, pick it in the AI translator settings after updating the translator to 2.0.0; the Custom picker needs 1.3.4.

**6. Translated subtitle upgrades are off after this upgrade.** The combined upgrade toggle is split in two (#476). Your manual-upgrade setting is kept as stored, or on if it was missing, and **Upgrade Translated Subtitles** starts off. If you relied on translations being replaced by provider subtitles, turn it on in **Settings > Subtitles**.

**7. The log file changes what it holds.** A normal install gains the provider lifecycle lines, roughly two per provider and one per scored candidate per search (#506). Debug mode caps `socketio.server`, `engineio.server` and `apscheduler` at WARNING. To debug those on purpose, name them in the new `log.verbose_loggers`, empty by default.

**8. Long actions answer at once and finish as jobs** (#526, #528, #529).

- A Discover **Download** queues a job instead of downloading while you wait. The file saves itself when the job finishes. If you left the page first, **Save** in the Jobs drawer gets it; the file is kept for up to 30 minutes.
- Saving language profiles, the embedded, audio and adaptive toggles, or a mass profile edit **no longer waits for the missing-subtitle scan**. The save returns immediately and a **Recalculating missing subtitles** job follows, so Wanted catches up a moment later.
- Provider Hub install, update, uninstall and catalog refresh, subtitle tools and mods, scan disk, series and league combine, and sports manual download answer with a job id. **If you script against the API**, those routes answer `202` now and the outcome is on the job; a subtitle mod that fails fails its job instead of answering 409.
- A manual download, upload or sync that fails is listed as failed with its reason, where it used to be listed as completed.

**9. On a fresh install**, Discover opens without a library, and the wizard asks which kind of install you are before building its steps. Sonarr is no longer required to finish it.

### Database Migrations

Schema changes run on boot, in create-all-then-migrate order, on SQLite and PostgreSQL alike:

- **Media server instance tables** (`c2e7a4d9f810`) for the shared media server layer, with per-instance URL, encrypted API key, TLS verification, path mappings, library selections, pending targets and status (#431).
- **`table_sports_file_index`** (`a6d8f2b9c103`), plus the two owned-event foreign keys in Sports history and blacklist gaining `ON UPDATE CASCADE` beside `ON DELETE CASCADE`. Existing data is preserved and the index is filled after startup (#432).
- **Media server convergence** (`e5b7d1c93a24`, #466): the shared table gains `refresh_movies`, `refresh_episodes` and a JSON `options` column, and both kind check constraints admit `jellyfin` and `plex`. The downgrade refuses while a Jellyfin or Plex row or import marker exists.

Nothing else changes the schema. Seerr, Statistics, the session hardening, the backup work, the container hardening and the jobs work all run against the existing tables.
