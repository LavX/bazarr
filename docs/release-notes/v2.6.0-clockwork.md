# Bazarr+ v2.6.0 (Clockwork)

Codename: **Clockwork**

Clockwork is a correctness pass across the whole surface: 79 pull requests that make the machinery keep honest time. Databases created by upstream Bazarr are adopted instead of crash-looping, sync results are held to the offset you configured instead of merely bounded by it, providers are scored on what they actually offer, and your subtitles are finally downloadable straight from the UI, single files or whole seasons at once. Most of this release exists because users filed precise, reproducible reports; the fixes below name them.

---

## Headline: Coming from upstream Bazarr just works now

If you pointed Bazarr+ at a config directory created by upstream Bazarr, it crash-looped on boot with `Can't locate revision identified by '0124f9e278fb'`: the upstream database carries migration revisions that were never part of the fork's chain, and Alembic refused to move.

Bazarr+ now detects an upstream-created database at startup and adopts it: the migration stamp is rewritten onto the fork's own chain and the one column upstream dropped is restored, after which the normal migration path proceeds. Nothing in your data is altered by the adoption itself.

> Adoption handles any upstream revision, not a hard-coded list. If upstream ships a new migration tomorrow, a database carrying it still adopts cleanly.

This was the single largest barrier to trying Bazarr+ on an existing install, and it is gone. Thanks to szab100 for the report that pinned the exact revision (#302).

---

## Download your subtitles

Every subtitle row in the UI now carries a **Download** action, and it works for everything Bazarr+ can produce, not just the file a provider gave you:

### Single files, any variant

The row menu downloads the exact file on disk: plain subtitles, hearing-impaired and forced variants, synchronized outputs (`en:hi:sync-ffsubsync` and friends), and combined dual-language subtitles (`en:combined-hu`). The served file is validated end to end: the endpoint refuses symlink swaps, checks the resolved path against your media folders, and sends the correct content type with sniffing disabled.

### Whole seasons and languages as zip bundles

The series and movie detail pages gained a bundle download in the header: one zip with every external subtitle, organized into `Season NN/` folders for series, with optional season and language filters. Bundles are streamed with a size budget, duplicate names are deduplicated case-insensitively, and files that vanish mid-build are skipped rather than corrupting the archive.

### The viewer is readable in light mode again

Cue timestamps in the subtitle viewer were nearly invisible in light mode. The contrast now holds in both themes.

> If a download ever comes back as a web page instead of a subtitle (an out-of-date backend behind an updated UI, for instance), the frontend now detects it and tells you, instead of saving junk with a `.srt` name.

## Sync that tells the truth

Subtitle synchronization had a habit of reporting success it had not earned. Clockwork makes the whole pipeline honest, and thanks to illusive888 for the report that started it (#308):

### Maximum offset is now an acceptance threshold

The configured maximum offset used to bound ffsubsync's search window, so a subtitle minutes out of sync could come back "synced" within the window and overwrite a good file. It is now an acceptance threshold: ffsubsync and autosubsync results beyond it are rejected outright, and the next engine in your fallback order gets its turn. alass reports no comparable offset, which is documented rather than papered over.

> Expect more honest failures. A file that previously "synced" into a ruined state now fails loudly, and files already ruined by the old behavior are not repaired by this release.

### Per-engine outcomes, real numbers

Sync history now records which engine ran and what it measured. autosubsync used to discard its completed sync behind an opaque quality-threshold failure; it now reports the shift it actually measured. alass no longer dies on MKVs whose attachment streams confuse ffprobe: a shim feeds it the stream data it expects.

### Release-type mismatches are detected and cleared

Bazarr+ notifies you when a subtitle's release type does not match your media file, and the indexer now clears stale mismatch records when the situation is resolved on disk, not only when a download fixes it.

## Providers: scored, gated, and steady

### Candidates are scored on their release information

Provider Hub candidates lost release-based scoring entirely when Provider Priority was disabled, so a perfect-release match and a wild guess scored the same. Hub candidates now match their release information against your file the way built-in providers always did (#305, illusive888).

### Weight one provider up or down

Each provider can carry a score modifier from -100% to +100%, applied before the minimum-score check. It is a percentage of the maximum score rather than raw points, so 25% on an episode is worth roughly 90. Built for keeping something like WhisperAI as a genuine last resort without lowering the bar for everyone else, which is exactly what Aracnoss asked for (#301).

> Related scoring correction: movie editions detected by GuessIt were dropped, so a "Director's Cut" subtitle scored as if editions matched. Editions now carry through, which means subtitles for edition-tagged movies can score up to 30 points lower than before. If a wanted movie suddenly stalls under your minimum score, this is why: the old score was inflated, not the new one wrong (#307, illusive888).

### RAR archives extract again

RAR extraction had silently broken in the shipped image, taking providers like prijevodionline with it. The image now ships `unar` and extraction works end to end, with the test split that had hidden the failure removed so it cannot silently regress. The community fix came from luminoso (#304, illusive888).

### Archive matching stopped being picky

Subtitle members inside archives are now matched case-insensitively, and the accepted extension list covers the canonical set including MicroDVD `.sub`, so Titlovi-style archives stop being rejected for cosmetic reasons (#306, illusive888).

### The pool stops resurrecting the dead

Two long-standing pool defects are fixed: a provider you disabled or that was throttled could be silently resurrected by pool re-registration, and a config change leaked the provider instance it replaced. Excluded providers are now genuinely excluded, quietly, without poisoning throttle bookkeeping.

### Four dead providers removed, and a third anti-captcha vendor

hosszupuska, podnapisi, subscenter and xsubs no longer exist as services and no longer exist in Bazarr+. On the other side of the ledger, **CaptchaAI** joins Anti-Captcha and DeathByCaptcha as a supported anti-captcha vendor, and embedded subtitle tracks that report bare alpha3 string language values are handled instead of dropped.

## Translate from an embedded track

If a release only carries its English subtitles inside the video container, mass translate can now extract and translate them. Enable "Treat Embedded Subtitles as Downloaded" so embedded tracks are indexed, then pick the source language as usual: when no external source file exists, the embedded track is extracted and used automatically. Each variant is handled separately, so a normal and a hearing-impaired track produce their own outputs.

---

## Multi-instance refinements

The multi-instance foundation from Murmuration gets a correctness pass of its own:

- **Per-instance default language profile.** Each Sonarr or Radarr instance can name the language profile its new media receives. Setting it changes nothing for existing media and nothing for single-instance installs; it does not retroactively reassign a library.
- Manual upload resolves episodes by their local id, and decides episode ownership by the owning series. Before this, uploading to a series whose upstream and local ids had drifted could offer the wrong series' episodes and **silently write a subtitle into the wrong show**. Files already misfiled are not repaired: the symptom to look for is a subtitle present for an episode you never uploaded one for (#312, reported by minhkhoi489-spec and two more users on the thread).
- Mass download maps series episode paths with the series mapping (it used the movie mapping), the ffprobe cache is keyed by the owning instance, and media cache invalidations key on local ids, so same-titled media on different instances stop cross-contaminating.

## Lighter and steadier

- **The web server thread pool is right-sized and configurable.** Bazarr+ ran 100 waitress threads and held memory to match; the default is now 32 (`web_server_threads`, valid 4 to 100). On a real 4-instance library this took the process from 123 threads and ~263 MB resident to 49 threads and a leaner footprint. Note that each open browser tab parks one worker on a long-poll, so very tab-heavy setups can raise the value back.
- glibc malloc arenas are capped in the image, and three code paths that held more memory than they were using were reworked.
- **The Jobs Manager respects its concurrency limit.** A check-then-act race let it run more jobs than configured; the slot is now reserved before the worker spawns (#331, pkoretic).

## Other Improvements & Fixes

- Combined subtitles resolve custom language tags like `zh-TW` as sources, and render like every other pill in the row.
- The Swagger UI serves its assets from the installed flask_restx again instead of 404-ing.
- Connection-test endpoints accept the API key from the header only, closing a query-string leak.
- The feature request issue template works again.
- The public site was rebuilt newcomer-first, with the animated Clockwork hero, and the README was brought in line with what v2.6.0 actually ships.
- The release process itself is now tooled: version stamp, notes scaffold with render check, a post-cut verifier, and the animated hero pipeline that produced the image at the top of this page.
- CI now runs every backend test file or excludes it by name with a stated reason: 66 test files that silently never ran are running.

### Provider catalog, on its own cadence

The Provider Hub catalog shipped alongside this cycle: **LegendasDivx** joins as a new provider (cloudscraper port with credentials support), Gestdown builds scene-style release names from the API episode object and leaves season packs' own release names alone, and OpenSubtitles.org resolves Serbian instead of guessing English. Catalog updates reach you through the Provider Hub directly, no Bazarr+ upgrade required.

- The image ships `unar` for RAR extraction and `mediainfo` alongside `ffprobe`.
- glibc malloc arenas are capped via `MALLOC_ARENA_MAX` in the image.
- Docker publishing is unchanged: versioned tags plus `latest` on release, `sha-*` pointers for every build.
- The backend test workflow runs the previously split test trees together again, with the RAR configuration pinned.

## Database Migrations

No schema changes. The upstream-database adoption step stamps an adopted database onto the fork's migration chain and restores one column upstream dropped; it does not alter your data, and existing Bazarr+ databases are untouched.

## Upgrade / Migration Notes

- No breaking changes. Update and restart as usual.
- Coming **from upstream Bazarr**: point Bazarr+ at your existing config directory and it adopts the database on first boot. Take a backup first, as you would for any migration.
- **Edition-tagged movies may score lower** than before (up to 30 points), because editions now participate in scoring instead of being dropped. If an upgrade stalls under your minimum score, the old score was inflated; adjust the minimum if needed.
- **Sync failures are more honest.** A sync beyond your configured maximum offset now fails and falls through to the next engine instead of writing a bad file. Files ruined by the old behavior are not repaired retroactively.
- **Web server threads** default to 32. Raise `web_server_threads` (Settings > General, 4 to 100) if you keep many browser tabs open; each tab parks one worker.
- The per-instance default language profile is opt-in and only affects newly added media.
- **PostgreSQL remains fully supported and first-class.**
