# TrueNAS isolated Arr and provider integration validation

Tested on 2026-09-29 in the retained disposable TrueNAS SCALE 25.10.7 VM described in [native-validation.md](native-validation.md). The same package-rendered Compose workload was reinstalled through the native TrueNAS custom-app API. This remains a custom-app test, not catalog ingestion or the default ixVolume lifecycle. The VM used only its virtual disks and generated media; no testbox media path was mounted.

## Observed gates

| Gate | Observation |
| --- | --- |
| Native app and web health | `app.create` job 83 succeeded. TrueNAS reported the custom app running and the Bazarr+ UI returned HTTP 200. The Bazarr processes ran as UID/GID 568. |
| Arr connections | Created one enabled default Sonarr instance and one enabled default Radarr instance through Bazarr's `/api/system/arr-instances` API. Both by-ID test calls returned `ok=true`, for Sonarr 4.0.19.2979 and Radarr 6.3.0.10514. The upstream bridge allowed read-only Arr GETs and rejected writes. No real Arr API key was printed or stored in this receipt. |
| Metadata sync | Enabled only the Sonarr and Radarr master switches through Bazarr's settings API. Their per-instance tasks completed. The isolated Bazarr database contained 285 series, 3,951 episodes, and 744 movies. `/api/series` and `/api/movies` reported the same series and movie totals. Subtitle history was empty before the provider test. An initial zero-series sync was a test-bridge trailing-slash rejection; after the bridge accepted that read-only URL, the retry imported the series. |
| Credential and config persistence | Native `app.stop`/`app.start` jobs 117/118 succeeded. The UI returned HTTP 200 and both saved Arr instances passed by-ID tests again, proving their encrypted API keys remained usable after restart. |
| Single synthetic movie fixture | One synced Radarr movie was mapped by an exact-path rule to a 2.005-second generated MPEG-4/AAC fixture in the VM's `/movies` dataset. The 2,688-byte file was owned by UID/GID 568. An English profile was assigned only to this movie, and automatic series/movie default profiles remained disabled. The original path string was read and stored in the isolated mapping, but no original video, subtitle, or config contents were copied from the testbox. |
| Provider installation | The official Provider Hub catalog initially returned zero cached entries because GitHub rate-limited its first refresh. The exact public My-Subs 0.1.3 manifest already cached by the parallel isolated test was submitted to Bazarr's normal `/api/provider-hub/installations` API. Its install job completed; the provider reported `active` and `enabled` after native stop/start jobs 137/138. The app UI returned HTTP 200 and both Arr tests still passed. |
| Provider search and download | An initial managed approval block prevented the search until the user explicitly approved sending one library movie's title and IMDb ID to anonymous My-Subs. After that approval, Bazarr's `/api/providers/movies` returned HTTP 200 with 103 English My-Subs candidates for the mapped fixture. One highest-scoring result was submitted through the same API, which returned HTTP 204. Bazarr's manual-download job 1 finished `completed`, without an error or stop. No provider account was created or used. |
| Actual subtitle file, index, and History | Bazarr's `/api/movies/history` returned HTTP 200 and one row for the selected local movie, with action 2, owner instance 2, provider `my_subs`, and English `en`. Independent read-only verification found the history subtitle path matched Bazarr's movie index and a real 118,792-byte subtitle file in the VM's synthetic movie dataset. Its SHA-256 was `e5e76b19b3832d992d760361a6838e308a765ea147d043964c3ee8edc453b204`; ownership was UID/GID 568 and SRT timestamps were valid. No subtitle was written to a testbox media path. |

The fixture, provider installation, Arr metadata, and downloaded subtitle are retained on the isolated VM's virtual disks. After independent host inspection, the VM was shut down gracefully, and its virtual disks were retained. This establishes one anonymous provider download through Bazarr's real search, download, file-write, index, and History path. It does not establish scanning real mounted media, remote notification writeback, catalog installation, or migration from an existing Bazarr database.
